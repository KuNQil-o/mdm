# 当前限制与上线前事项

V3 本地验收基于真实 PostgreSQL、独立开发 ERP HTTP/事实数据库和 Chromium。它不能替代 PRD 18.4 要求的至少一个真实 ERP/接口平台写回 UAT，也不代表已进行生产发布。

1. 企业正式料号段、位数、字典、Identity 和流水重置策略尚未提供。验收使用独立指定预期字符串的示例元数据，不能视为企业编码规则签收。
2. PERF-009 的 5 万条容量验收尚未执行；大规模扫描目前采用 fetchSize 读取后在内存汇总候选，生产扩展需分页/分段提交设计及容量基线。单次 P95 和 100 并发结果仅是本机抽样。
3. JDBC 当前适配 PostgreSQL；复杂 Oracle/MySQL DDL 需 JDBC/手工结构兜底及相应驱动。FILE 类型可登记结构，但文件读取/回执适配器尚未实现。
4. 开发登录只在 dev profile 可用。生产 SSO/OIDC、TLS、来源秘密管理、实际网络授权需部署集成；默认部署白名单只允许本地开发 ERP。
5. 配置设计支持 JSON 编辑器；类别树、成员/岗位/字典治理已有 API，当前 V3 页面尚未提供完整可视化管理。Schema 条件/规则仍需熟悉配置表达式。
6. 指标样本在进程内保留最近 2000 次，重启后重新采集；没有生产指标仓库或报警通知接入。REST 连接健康未采集时明确显示未采集。
7. 双库备份摘要验证在停止应用的本地演练下完成；真实 ERP 通常由企业负责备份，仍需协调恢复点、RPO/RTO 与任务核对。
8. 当前浏览器为 Chromium 151。前端使用 JSON.parse 原始十进制 token 能力，企业旧 Chrome/Edge 必须补充兼容验收。

V2 历史表及内部回归保留，写入口与旧 Worker 默认停用。它们不作为 V3 物料事实源。没有开展 IFS/KRS 系统迁移、BOM/库存/工艺迁移或生产数据切换。
