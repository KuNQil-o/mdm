# 通用 MDM 料号平台测试用例 V1.0

## 1. 文档目的

本测试用例以《IFS9.0料号系统操作手册V0.1》作为**业务参考样本**，用于验证新设计的通用 MDM 料号平台是否能够覆盖类似 ERP 料号系统中的业务复杂度。

本方案**不涉及现有 ERP 系统迁移、替换、数据切换或兼容改造**。手册中的化学品、玻璃布、铜箔、压片、胶片、基板、成胶、一般物料、耗材等模块，仅作为 MDM 建模、规则配置和料号生成能力的真实业务样本。

测试的核心目标是验证：

1. 不修改 MDM 核心代码，仅通过配置即可支持不同物料类别；
2. 一个物料的数据可以来自一张或多张源表；
3. 多张参考表中的代码和值可以共同参与料号生成；
4. MDM 能区分“ERP/source record identity”和“material identity”；
5. 同一组业务属性生成稳定、唯一、可追踪的料号；
6. 不同类别可使用完全不同的编码规则；
7. 料号生成完成后，可被 ERP、库存、BOM、工艺等下游系统继续使用；
8. 规则、Schema、Dataset、Mapping 均可版本化并保留历史解释能力。

## 2. 测试对象

### 2.1 MDM 核心链路

```text
Source System
    ↓
Source Object
    ↓
Source Dataset
    ↓
Field Mapping
    ↓
MDM Schema
    ↓
Material Identity
    ↓
Validation / Derivation
    ↓
Code Rule
    ↓
Material Number
    ↓
Assignment Ledger
    ↓
Downstream ERP / Inventory / BOM / Routing
```

### 2.2 参考业务类别

| 类别 | 手册中的主要编码相关字段 |
|---|---|
| 化学品 | 包装方式、化学品分类、化学品型号、化学品厂商、等级 |
| 玻璃布 | 玻璃布种类、布种代码、玻璃布厂商、表面处理、形式、幅宽、等级 |
| 铜箔 | 铜箔分类、铜箔基重、铜箔制造商、表面处理、颜色、尺寸、等级 |
| 压片 | 产品类别、生产制程、玻璃布分类、布种代码、压片特性规格、玻璃布厂商、流水码、尺寸 |
| 胶片 | 产品类别、生产制程、玻璃布分类、布种代码、产品规格(R/C)、流水码、尺寸或裁切 |
| 基板 | 产品类别、生产制程、厚度代码、基板叠构、铜箔类型、流水码、尺寸或裁切 |

# 3. 测试数据设计

## 3.1 基础数据

每个类别至少准备：

- 10 组正常数据；
- 5 组边界数据；
- 3 组重复 Identity 数据；
- 5 组缺失/非法数据；
- 3 组参考数据失效场景；
- 2 组规则升级前后的历史样本。

## 3.2 玻璃布复杂数据集

建议模拟以下源对象：

```text
GLASS_CLOTH                 玻璃布主表
GLASS_CLOTH_TYPE            玻璃布类型
GLASS_CLOTH_WEIGHT          布种/基重
GLASS_CLOTH_MANUFACTURER    制造商
GLASS_CLOTH_TREATMENT       表面处理
GLASS_CLOTH_FORM            形式
GLASS_CLOTH_WIDTH           幅宽
GLASS_CLOTH_GRADE           等级
```

典型主表关联：

```text
GLASS_CLOTH
 ├── TYPE_ID          → GLASS_CLOTH_TYPE
 ├── WEIGHT_ID        → GLASS_CLOTH_WEIGHT
 ├── MANUFACTURER_ID  → GLASS_CLOTH_MANUFACTURER
 ├── TREATMENT_ID     → GLASS_CLOTH_TREATMENT
 ├── FORM_ID          → GLASS_CLOTH_FORM
 ├── WIDTH_ID         → GLASS_CLOTH_WIDTH
 └── GRADE_ID         → GLASS_CLOTH_GRADE
```

| CORE-021 | P0 | Schema 版本升级 | 新增必填字段并发布 v2 | 老记录按 v1 解释，新记录按 v2 校验 |

| CORE-023 | P0 | 正式生成 | 调用 assign/generate | 原子写 Assignment Ledger 后返回正式料号 |
| CORE-024 | P0 | 重试 | 客户端超时后使用相同幂等键重试 | 返回原结果，不再占用新号 |
| CORE-025 | P0 | 审计追踪 | 查看一次发号记录 | 可查 source、dataset、schema、identity、rule version、输入快照、结果、时间和 traceId |

# 20. 端到端验收场景

## E2E-01 玻璃布多表发号

1. 在 ERP 模拟库创建玻璃布主记录；
2. 主记录引用玻璃布种类、布种基重、厂商、表面处理、形式、幅宽、等级；
3. MDM Source Dataset 完成多表 Join；
4. Mapping 输出统一的 GlassCloth Schema；
5. Identity Engine 计算规范化 Material Identity；
6. Validation Rule 校验所有引用和业务组合；
7. Code Rule 生成候选料号；
8. 正式 assign；
9. Assignment Ledger 保存规则版本和输入快照；
10. 返回/回写业务系统。

**验收：**
- 无行业专用 Java 分支；
- 所有字段来源可追踪；
- Join 不产生重复粒度；
- 料号唯一；
- 同 Identity 重试得到同号；
- 规则版本可追踪。

## E2E-02 胶片尺寸/裁切条件规则

1. 配置胶片 Schema；
2. 配置 `size XOR cut` 校验；
3. 分别执行 size 模式和 cut 模式；
4. 测试两者同时存在与同时不存在。

**验收：**
- 合法的两种模式均能生成料号；
- 非法组合均被规则引擎阻止；
- 不需要在 Java 中写 `if (category == FILM)` 的专属逻辑。

## E2E-03 基板复杂参考数据

1. 创建产品类别、生产制程、厚度、叠构、铜箔类型、流水码、尺寸/裁切；
2. Dataset/Mapping 形成统一 Schema；
3. 使用当前规则正式发号。

**验收：**
- 引用表变化可被识别；
- 铜箔类型等参考数据正常映射；
- Identity 唯一；
- 发号后修改编码依赖属性不会静默重编码。

## E2E-04 下游 BOM 和工艺

1. 通过 MDM 生成一个正式料号；
2. 在模拟 ERP 中建立库存件；
3. 使用该料号查询并建立 BOM；
4. 使用该料号查询并建立工艺路线。

**验收：**
- MDM 只提供稳定料号及必要身份；
- BOM 和工艺仍由各自业务模块管理；
- BOM/工艺变化不反向修改 MDM 料号。

# 21. 最终验收门槛

P0 上线建议至少满足：

1. 玻璃布、铜箔、胶片、基板至少四种差异明显的物料模型通过端到端测试；
2. 玻璃布必须通过多表 Dataset 测试；
3. 胶片、基板必须通过条件校验/XOR 测试；
4. 并发正式发号重复率为 0；
5. 相同幂等请求重复占号为 0；
6. 不同 Identity 同码时必须被阻止；
7. 历史规则版本可以准确解释已发料号；
8. Source Record Identity 与 Material Identity 可独立查询；
9. MDM 核心代码不得包含针对“玻璃布/铜箔/胶片/基板”的业务分支；
10. 新增一种测试物料类别，应仅通过配置完成，不要求修改领域代码；
11. MDM 发出的料号能被下游库存、BOM、工艺测试系统正常使用；
12. 所有正式 Assignment 均可追踪至 Source、Schema、Identity、Code Rule Version 与原始输入快照。
