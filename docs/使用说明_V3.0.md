# 通用料号与物料主数据平台使用说明（V3.0）

本文面向业务操作人员、配置设计人员、发布审核人员及管理员，依据当前 V3 页面和接口编写。需求以 [PRD V3.0](通用料号与物料主数据平台_PRD_V3.0.md) 为准，业务验收依据 [测试用例 V1.0](MDM料号平台_测试用例_V1.0.md)。

## 1. 平台的用途

ERP 保存物料事实；MDM 从 ERP 读取数据，完成标准化、身份识别、业务校验和料号生成，保存不可变发号台账，再通过回写任务把正式料号同步到 ERP。

日常操作的顺序是：**确认 ERP 记录 → 预览数据和料号 → 正式发号 → 查看台账 → 确认 ERP 回写结果**。物料属性有误时，应在 ERP 修正；BOM、库存和工艺由下游系统维护。

配置链路如下：

```text
Source System → Source Object → Source Dataset → Field Mapping → Schema
→ Material Identity → Validation/Derivation → Code Rule → Assignment Ledger → ERP Writeback
```

执行时先完成标准化、派生和校验，再计算 Identity，最后正式发号。

| 名称 | 用途 |
| --- | --- |
| Source System（来源系统） | 登记 ERP 数据库、REST 服务或接口平台的连接信息 |
| Source Object（来源对象） | 描述表、视图或 API 对象的字段、类型、主键和结构版本 |
| Source Dataset（来源数据集） | 配置主表、参考表关联、来源键、物料粒度和输出字段 |
| Field Mapping（字段映射） | 把 Dataset 输出转换为 Schema 属性，处理单位和字典映射 |
| Schema | 定义属性类型、必填、枚举、派生表达式和业务校验 |
| Material Identity（物料身份） | 通过完整规范属性组合识别同一种物料 |
| Code Rule（料号规则） | 配置常量、属性、字典、流水和周期等编码段 |
| 组合发布包 | 固定上述配置版本、验证样本和 ERP 回写契约 |
| Assignment Ledger（发号台账） | 记录正式号、来源、身份及当时使用的配置和输入 |

**来源键、Identity、料号是三个不同概念。** 来源键定位 ERP 记录，Identity 判断业务物料是否重复，料号供 ERP 和下游系统使用。两个不同来源键具有相同 Identity 时，系统会提示身份冲突，需要核对 ERP 数据或身份配置。

## 2. 打开系统与选择身份

已部署环境通过环境提供的前端访问入口打开；本机开发环境使用 `http://localhost:5173`。

1. 在“当前用户”选择用户，点击“登录 / 切换用户”。
2. 在“当前租户”选择本次操作所属租户。
3. 从左侧菜单进入相应模块。切换租户后，重新选择来源和配置。
4. 操作后可点击页面刷新按钮获取最新状态。

开发环境的初始用户如下，实际可操作范围以授权为准：

| 用户 | 主要用途 |
| --- | --- |
| `editor` | 设计来源、Dataset、Schema 和规则，提交发布，进行集成操作 |
| `reviewer` | 审核发布包，进行集成操作 |
| `admin` | 管理和排查问题 |
| `reader` | 查看授权范围内的配置和记录 |

开发环境提供 `TENANT-A`、`TENANT-B`。上述账号切换属于开发登录功能，生产身份接入见 [当前限制](known-issues.md)。发布包的提交人与最终审批人必须不同，即使使用管理员也需遵守这一规则。

## 3. 第一次操作：使用已有配置发号

### 3.1 在 ERP 测试页面直接申请

开发环境运行 `scripts/seed.sh` 后，打开前端入口的 `/erp/`，也可点击 MDM 左侧“打开 ERP 测试页面”。该页面无需登录 MDM：

1. 选择厂商、布种/基重、表面处理、幅宽、形态和等级，填写备注。
2. 点击“保存并申请料号”。ERP 先保存主表记录，再以服务端来源身份调用 MDM；MDM 读取主表及参考表、标准化、校验、计算 Identity 并原子发号。
3. 返回的正式号自动写入 ERP 的“玻璃布料号”字段，页面提示可继续原业务流程；开发示例为 `GC` 加六位流水。
4. 若只想先保存，点击“仅保存”，随后使用“申请 / 重试料号”。
5. 出错后保持同一来源键，修正后重试；同一规格建立另一条 ERP 记录会触发身份冲突。重复测试新物料时，应调整实际规格组合。

记录列表提供打开、详情和刷新功能，刷新页面仍可查看已保存的物料和料号。演示规则可以在 MDM 中按正常版本发布流程调整。完整说明见 [ERP 模拟器测试说明](ERP模拟器测试说明.md)。

### 3.2 在 MDM 控制台预览和发号

本流程适用于已有“已发布”组合版本的 Dataset。先在 ERP 准备一条符合该 Dataset 候选条件、尚未发号的记录，并取得它的稳定来源键。

1. 打开“Dataset 构建”，在“打开已有 Dataset”中选择目标版本，确认来源和 Dataset code。
2. 在“预览来源键”输入 ERP 记录的来源键。单字段键填写原值；组合键按配置顺序填写 JSON 数组字符串，例如 `["ORG01","100001"]`。
3. 点击“读取真实数据预览”，检查主表、参考表关联后的输出是否正确。这一步使用所选 Dataset 版本。
4. 点击“按默认发布规则预览料号”，检查规范属性、Identity 和候选料号。这一步按 Dataset code 查找默认发布包，不一定使用页面当前选中的草稿版本。
5. 预览通过后，点击“从 ERP 记录申请正式号”。系统持久化正式号和台账，并建立独立回写任务。
6. 打开“发号台账”，找到该来源键和料号，点击“解释料号”查看生成依据。
7. 打开“ERP 回写”，查看对应任务。最终以 `SUCCEEDED`（业务成功）及 ERP 中一致的料号确认流程完成。

预览不会占用流水；含流水的候选号可能显示 `{流水:6}`，正式发号时才分配实际数字。正式号已生成和 ERP 已回写是两个独立结果，需分别查看。

人工发号要求来源连接配置明确设置 `allowManualAssign: true`。若提示 `MANUAL_ASSIGN_DISABLED`，应使用该来源授权的 ERP 接口或 Dataset 扫描流程。

同一来源记录重复请求不会重复分配正式号。页面提示“请求结果待确认”时，先查看台账，并在当前页面以相同参数重试；页面会复用该不确定请求的幂等键。

## 4. 登记来源系统与来源对象

### 4.1 登记并启用来源

在“来源系统与对象”选择来源类型，填写“新来源 code”和连接配置，点击“登记来源”，再点击“测试连接并启用”。

开发 ERP 数据库连接配置示例：

```json
{
  "jdbcUrl": "jdbc:postgresql://localhost:5432/mdm_erp_v3",
  "userEnv": "ERP_READ_USER",
  "passwordEnv": "ERP_READ_PASSWORD",
  "writebackBaseUrl": "http://127.0.0.1:9092",
  "allowManualAssign": true
}
```

此地址用于后端连接开发 ERP。真实来源须由管理员配置目标地址授权和凭据绑定；配置只填写凭据的环境引用名，不填写实际密码或 Token。JDBC 读取使用只读账号，ERP 回写使用独立接口。

### 4.2 建立 Source Object

页面提供三种方式：

| 方式 | 操作 |
| --- | --- |
| JDBC 元数据 | 选择已登记来源，把“连接配置 / 扫描对象清单”文本框内容改为对象清单，点击“读取 JDBC 元数据” |
| DDL 文本 | 在右侧文本框粘贴 `CREATE TABLE ...`，点击“解析 DDL 为草稿” |
| API 契约 | 在右侧文本框粘贴对象结构 JSON，点击“登记 API Object JSON 契约” |

JDBC 对象清单示例：

```json
[
  {"objectName": "cloth"},
  {"objectName": "manufacturer"},
  {"objectName": "cloth_weight"},
  {"objectName": "cloth_type"},
  {"objectName": "treatment"},
  {"objectName": "form_ref"},
  {"objectName": "width_ref"},
  {"objectName": "grade_ref"}
]
```

该文本框同时用于连接配置和扫描对象清单；登记来源时输入对象，读取元数据时输入数组。DDL 导入只解析结构文本，不会在 ERP 执行建表。

点击对象列表中的记录查看字段、主键和版本。配置 Dataset 时选择明确的对象版本；ERP 结构变化后登记新版本，并检查依赖影响，不会自动改写原发布包。

## 5. 配置多表 Dataset：玻璃布示例

在“Dataset 构建”选择来源、填写 Dataset code，选择主表对象版本和别名。玻璃布示例以 `cloth` 为主表，别名 `g`，来源键输入 `id`，物料粒度选择 `ONE_ROOT_ROW_ONE_MATERIAL`，表示一条主表记录对应一个候选物料。

点击“增加参考表”，逐项选择参考对象版本、别名及等值关联字段。开发 ERP 示例：

| 参考表 | 别名 | 关联条件 |
| --- | --- | --- |
| `manufacturer` | `m` | `g.manufacturer_id = m.id` |
| `cloth_weight` | `bw` | `g.weight_id = bw.id` |
| `cloth_type` | `t` | `bw.type_id = t.id` |
| `treatment` | `tr` | `g.treatment_id = tr.id` |
| `form_ref` | `f` | `g.form_id = f.id` |
| `width_ref` | `w` | `g.width_id = w.id` |
| `grade_ref` | `gr` | `g.grade_id = gr.id` |

参考关联可配置 `LEFT` / `INNER` 和 `1:1` / `N:1`。示例使用 `LEFT`、`N:1`、未命中策略 `ERROR`。同一主表记录匹配多条参考记录会造成粒度冲突，应修正关联条件或参考数据；不能随意取第一条记录继续发号。

通过“增加输出”配置逻辑字段：

| 输出名 | 来源字段 |
| --- | --- |
| `type` | `t.code` |
| `clothCode` | `bw.cloth_code` |
| `manufacturer` | `m.code` |
| `treatment` | `tr.code` |
| `form` | `f.code` |
| `width` | `w.width` |
| `widthUnit` | `w.unit` |
| `grade` | `gr.code` |
| `remarks` | `g.remarks` |

同时设置“已有 ERP 料号字段”为 `g.material_no`，“来源版本字段”为 `g.version`，并选择增量策略。保存为新版本草稿，再用真实来源键进行预览。

候选过滤条件 `candidateFilter`、关联有效性 `activeField` / `activeValue`、默认值型未命中策略等高级配置通过 [API](api.md) 维护。当前表单未覆盖全部高级字段；为已有复杂 Dataset 创建新版本时，通过 API 保留完整定义并复核。系统不接受任意 SQL，复杂取数逻辑可由 ERP 只读视图提供。

## 6. 配置 Schema、Mapping、Identity 和 Code Rule

在“Schema 与规则”创建或选择类别，选择配置类型，在 JSON 编辑器中填写定义，点击“保存为新版本草稿”。Mapping、Identity 和 Code Rule 还需填写配置 code；Schema 归属所选类别。点击版本清单可把现有定义载入编辑器。

以下均为配置示例，不代表企业正式料号规则。玻璃布、胶片等类别差异通过元数据表达。

### 6.1 Schema：属性与约束

Schema 使用 `attributes` 描述属性，使用 `validations` 描述业务校验。玻璃布属性示例：

```json
{
  "attributes": [
    {"code": "type", "type": "STRING", "required": true, "searchable": true},
    {"code": "clothCode", "type": "STRING", "required": true, "searchable": true},
    {"code": "manufacturer", "type": "STRING", "required": true, "searchable": true},
    {"code": "treatment", "type": "STRING", "required": true, "searchable": true},
    {"code": "form", "type": "STRING", "required": true, "searchable": true},
    {"code": "width", "type": "DECIMAL", "unit": "mm", "scale": 3, "precision": 12, "min": 0, "required": true, "searchable": true},
    {"code": "grade", "type": "STRING", "required": true, "searchable": true},
    {"code": "remarks", "type": "STRING"}
  ],
  "validations": []
}
```

支持字符串、整数、小数、布尔、日期、枚举和引用属性。单位、精度、枚举有效性及必填条件按 Schema 校验；ERP 物料引用需配置对应 ERP Dataset 和有效性规则。

### 6.2 Mapping：逻辑输出到规范属性

```json
{
  "fields": [
    {"target": "type", "source": "type"},
    {"target": "clothCode", "source": "clothCode"},
    {"target": "manufacturer", "source": "manufacturer"},
    {"target": "treatment", "source": "treatment"},
    {"target": "form", "source": "form"},
    {"target": "width", "source": "width", "unitSource": "widthUnit"},
    {"target": "grade", "source": "grade"},
    {"target": "remarks", "source": "remarks"}
  ]
}
```

这里的 `source` 指 Dataset 输出名称。`unitSource` 取来源单位，再按 Schema 单位标准化。常量、表达式、字典转换和跨 Dataset 投影的约定见 [API 文档](api.md)。

### 6.3 Identity：识别业务重复

```json
{
  "fields": [
    {"field": "type", "allowNull": false},
    {"field": "clothCode", "allowNull": false},
    {"field": "manufacturer", "allowNull": false},
    {"field": "treatment", "allowNull": false},
    {"field": "form", "allowNull": false},
    {"field": "width", "allowNull": false},
    {"field": "grade", "allowNull": false}
  ]
}
```

示例将七个业务属性组合为身份，备注不参与身份。Identity 应按真实业务粒度设计；系统使用完整规范身份判断重复，哈希仅辅助定位。

### 6.4 Code Rule：组成料号

```json
{
  "separator": "-",
  "segments": [
    {"type": "CONST", "value": "GCDEMO"},
    {"type": "ATTR", "field": "type"},
    {"type": "ATTR", "field": "clothCode"},
    {"type": "ATTR", "field": "manufacturer"},
    {"type": "ATTR", "field": "treatment"},
    {"type": "ATTR", "field": "form"},
    {"type": "ATTR", "field": "width"},
    {"type": "ATTR", "field": "grade"}
  ]
}
```

当规范属性为 `E / 7628 / HH / A / R / 1270 mm / A` 时，示例候选号为 `GCDEMO-E-7628-HH-A-R-1270-A`。需要流水时可增加 `{"type":"SEQUENCE","name":"MAIN","width":6}`。周期重置须配置相应周期段和固定时区。

### 6.5 胶片、基板：尺寸与裁切二选一

在 Schema 中分别定义 `size` 和 `cut`，两者不设无条件必填，通过业务校验要求恰好填写一个。以下为加入 Schema 的 `validations` 片段：

```json
[
  {
    "field": "size",
    "assert": {
      "op": "ne",
      "args": [
        {"op": "exists", "args": [{"field": "size"}]},
        {"op": "exists", "args": [{"field": "cut"}]}
      ]
    },
    "message": "尺寸与裁切必须且只能选择一个"
  }
]
```

需要统一编码属性时，可增加派生属性 `variant`，表达式为 `{"op":"coalesce","args":[{"field":"size"},{"field":"cut"}]}`，并由 Code Rule 引用。尺寸和裁切属性须有各自的有效值约束。

发布前至少验证以下组合，不能用默认值掩盖未填写情况：

| 尺寸 | 裁切 | 预期 |
| --- | --- | --- |
| 有效尺寸 | 未填 | 通过 |
| 未填 | 有效裁切 | 通过 |
| 未填 | 未填 | 拒绝 |
| 有值 | 有值 | 拒绝 |
| 非法尺寸 | 未填 | 拒绝 |
| 未填 | 非法裁切 | 拒绝 |

## 7. 验证并发布组合版本

1. 进入“组合发布”，选择类别及明确的 Dataset、Schema、Mapping、Identity、Code Rule 版本。
2. 在“Golden Samples 与回写契约”填写验证定义。样本来源键必须对应实际来源记录；预期料号应由业务规则独立确定。
3. 点击“新建发布草稿”，再点击该记录的“样本验证”，检查结果。
4. 由设计人员点击“提交”。若存在依赖、类型、样本或 ERP 契约错误，先修正并重新验证。
5. 切换到另一名有权限的审核人员，点击“审批发布”。
6. 在需要作为日常发号依据的已发布版本上点击“设为默认”，然后按第 3 节复核预览。

对应第 6 节玻璃布示例的发布定义如下。来源键须替换为真实值，样本属性须符合示例预期：

```json
{
  "samples": [
    {
      "sourceRecordKey": "替换为真实来源键",
      "expectedMaterialNo": "GCDEMO-E-7628-HH-A-R-1270-A"
    }
  ],
  "writeback": {
    "baseUrl": "http://127.0.0.1:9092",
    "path": "/writeback/cloth/{key}",
    "queryPath": "/writeback/cloth/{key}",
    "contractPath": "/contract",
    "businessValidationPath": "/contract/validate",
    "conditionalEmptyWrite": true,
    "supportsIdempotency": true
  }
}
```

若规则包含六位流水，正样本预期号使用 `{流水:6}` 占位。负样本使用 `valid: false` 和实际预期 `errorCode`；发布包至少需要一个成功样本。真实 ERP 需配置实际接口及等价契约，不能直接沿用开发服务地址。

已发布内容不可原地修改。调整规则应建立新版本并重新发布；将旧的可用发布包设为默认可切换后续发号依据，既有台账继续使用当时固定的版本。撤回、驳回、停用和影响分析目前由 [发布接口](api.md) 提供。

## 8. 扫描与自动处理

“Dataset 构建”中的“扫描当前发布版本”会创建一次扫描任务。进入“扫描任务”查看扫描数量、失败数量和详情，再到“异常工作台”查看具体记录的处理错误；扫描失败后先排查详情，修复后重新发起扫描。

扫描按默认发布配置处理候选来源记录。已发号记录通过台账和身份检查避免重复发号，已有 ERP 料号按发布策略处理。增量依据来源版本、更新时间或所选策略；参考表变化后的重扫策略也应配置。

**发布配置不等于启用定时轮询。** 定时扫描由集成人员通过 `/api/v1/source-datasets/{id}/runtime` 接口配置 `enabled`、`intervalSeconds`，当前页面没有定时开关。ERP 主动请求则使用绑定该租户及来源的客户端身份调用预览/发号接口。

暂停来源或租户会保留台账、任务和游标，并阻止新的业务处理。暂停与恢复由授权人员通过管理接口操作。

## 9. 查台账与解释料号

在“发号台账”选择类别、可搜索属性及比较方式，输入值后点击“类型化搜索”。只有已发布 Schema 标记 `searchable` 的属性可作为属性条件。

- 字符串、枚举：填写实际值。
- 小数、整数：填写数值，例如 `1270`；页面按该属性配置的单位构建条件。
- 布尔：填写 `true` 或 `false`。
- 引用：填写符合属性定义的引用 JSON。

点击“解释料号”查看来源记录、原始输入、标准化属性、完整 Identity、配置版本、编码段、流水和回写任务。新规则发布后，历史解释仍依据原版本。

台账不可编辑或删除。若 ERP 在发号后改变身份或编码属性，系统会记录异常；应核对是否属于新物料，必要时在 ERP 建立新记录并申请新号。

## 10. ERP 回写与异常处理

“ERP 回写”记录每次发号后的同步任务。“详情”显示状态与错误；“查询并处理”按回写策略查询 ERP 并继续处理。

| 状态 | 含义与操作 |
| --- | --- |
| `PENDING` | 待处理，等待后台或执行“查询并处理” |
| `SENDING` | 正在发送，查看后续确认结果 |
| `WAIT_CONFIRMATION` | 待确认，需查询 ERP 实际值 |
| `RETRY_WAIT` | 等待重试，修复接口或数据问题后查看恢复情况 |
| `RESULT_UNKNOWN` | 结果未知，先查询 ERP；确认情况后使用“修正后重试” |
| `FAILED` | 失败，修正原因后使用“修正后重试” |
| `SUCCEEDED` | 已确认业务成功 |

系统先查询 ERP：值与原正式号一致则确认成功；值为空才允许条件写入；存在其他非空号则报冲突。网络超时不能据此认定 ERP 未写入。重试沿用原正式号，不重新发号。

需要更换回写适配器时，由集成人员发布新配置，再通过任务 `rebuild` 接口重建任务，保留原号、稳定幂等键和历史任务链；当前页面未提供此按钮。

“异常工作台”用于处理来源读取、关联、标准化、身份和发号错误：先点击“详情”，修正 ERP 数据或配置，再点击“修正后重试”。常见问题如下：

| 错误码 | 处理方向 |
| --- | --- |
| `SOURCE_INCOMPLETE` | 核对来源字段、参考记录和 Mapping 是否完整 |
| `GRAIN_CONFLICT` | 核对关联条件，消除同一主表记录的多条匹配 |
| `VALIDATION_ERROR` | 按字段提示修正必填、枚举、范围或二选一规则 |
| `IDENTITY_CONFLICT` | 核对重复物料，必要时在 ERP 合并或修正身份粒度 |
| `CODE_CONFLICT` | 核对编码段是否充分区分物料，修正规则并重新发布 |
| `IDENTITY_CHANGED_AFTER_ISSUE` | 核对已发物料的身份或编码属性变更，按新物料处理 |
| `ERP_VALUE_CONFLICT` | 核对 ERP 当前号与台账号，人工确认业务原因 |
| `MANUAL_ASSIGN_DISABLED` | 改用授权来源客户端或扫描流程 |
| `SOURCE_PAUSED` | 确认来源状态，由授权人员恢复后继续处理 |

提交问题时提供当前租户、来源、Dataset/发布版本、来源键、错误码及追踪编号；不要附带实际凭据。

## 11. 日常检查与对账

打开“工作概览”查看任务和异常，点击“运行指标与连接状态”查看连接、延迟和错误信息。日常重点核对未完成回写、结果未知任务及新增处理异常。

在“组合发布”对已发布记录点击“对账”，检查 ERP 空号、号码不一致、未确认、缺少任务以及 ERP 有号但没有 MDM 台账等差异。对账只登记差异，不会直接覆盖 ERP。

回写 Worker 启用时，系统默认每日 **02:00 UTC（北京时间 10:00）** 对运行配置关联的已发布版本执行定时对账，要求租户和来源均处于启用状态。页面时间字段可能保留接口时区；比对记录时应注意 `Z` 表示 UTC。

## 12. 开发环境启动与管理员维护

首次启动在云工作区执行：

```bash
cd /workspace/mdm
bash scripts/install.sh
bash scripts/start.sh
bash scripts/seed.sh
```

端口分别为前端 `5173`、后端 `8080`、开发 ERP `9092`、PostgreSQL `5432`。已发布环境无需为日常操作重复安装。

需要用于页面演示的完整 V3 配置和来源记录时，可在开发环境执行：

```bash
bash scripts/test.sh http
```

该命令执行 HTTP 验收并持久保存独立前缀的配置和开发 ERP 记录。每次运行使用新前缀；在 `.runtime/v3-acceptance-fixtures.json` 中查看本次类别、Dataset、发布版本及来源键。选择与该配置匹配的来源记录，不要直接把默认输入 `100001` 当作任意 Dataset 的有效样本。

停止应用使用 `bash scripts/stop.sh`，再次启动使用 `bash scripts/start.sh`；停止应用保留数据库和卷。后端重新构建后需停止并重新启动以加载新构建。

备份、重启及恢复演练见 [运行与恢复](operations.md)，测试命令见 [测试说明](testing.md)。恢复演练由管理员在开发环境执行；正式备份需协调平台库与 ERP 的恢复点。

当前版本的真实 ERP UAT、企业正式编码规则、生产身份接入和容量验证进展见 [已知限制](known-issues.md) 及 [验收报告](acceptance-report.md)。JDBC 当前支持 PostgreSQL，文件读取适配器尚未实现。更详细的高级配置及接口参数见 [API 文档](api.md)。
